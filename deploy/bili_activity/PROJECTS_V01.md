## 项目如何推进

1. 启用后，生活轮次可用 `df_project create` 将本轮已有、未完成的目标加入项目，记录主题和理由。最多同时保留两个活动/暂停项目，暂停也占名额，避免无限堆积。
2. 研究与写作继续使用 `df_goal`、`df_workshop` 等原工具。一次运行完成不等于目标完成；没有可核对的作品不能进入项目回看。等待审批或受阻的目标不会被项目功能放行。
3. 目标完成后，默认至少等待24小时，再参加原调度器的候选排序。计时依据既有目标的 `updated_at`，后续追加关联来源可能延后回看；不保证恰好24小时启动。
4. 回看轮次只提供 `df_project`、`df_workshop`、`df_recall`、`df_life_status`。它不领取手机、不检查手机在线、不提供发布、联系或外部读取工具。手机正在被前台使用时，也可按原预算回看已有资料。
5. `review` 必须写有依据的收获与局限，可选写后续问题。回看绑定作品ID、版本、正文哈希和来源列表；同阶段相同参数可重放，改参数被拒绝。空问题表示收尾；达到项目创建时冻结的阶段上限也收尾，不自动另开项目。
6. 有新问题时，`advance` 仅创建一个 `ready` 目标，不在本回看轮次研究或写作。下一轮由原调度器决定是否推进，仍受原审批、设备、预算等限制。

回看是自身解释，不是事实核实结论；作品有效仅表示当前来源与结构可用，不证明内容正确或已经发布。明确拒绝与已有阶段标题完全相同的问题（忽略空白和大小写），但不声称具备语义去重能力。

当节律开启时，睡眠与活动后留白仍选择休息；睡前可回看已有作品。无进展的重复回看沿用原生活决策冷却，不会连续反复执行。

## 查看与管理

新工具 `df_project`：

| action | 用途 |
| --- | --- |
| list | 只读项目索引：ID、标题、状态、阶段数、上限、更新时间 |
| read | 只读阶段目标、作品版本、回看、来源和当前有效性；资料标为非指令 |
| create | 挂到已有目标上；普通后台只能使用本轮目标 |
| review | 指定已完成阶段，保存收获、局限、可选问题 |
| advance | 指定已回看的原阶段，为其创建下一阶段；重放仍用原阶段序号 |
| pause / resume | 主人可暂停/恢复；专门回看轮次也可暂停当前项目 |
| archive | 主人归档；当前阶段目标必须已完成或取消，不解除审批或抹去未完成任务 |

`df_life_status.projects` 返回开关状态与只读索引。详细作品正文仍通过 `df_workshop read` 获取；来源原文通过 `df_recall` 的经历ID追溯。

前台修改先暂停后台并重新检查配置。非主人、外会话、公开回复监听不能使用项目工具；回看轮次不能改其他项目、其他阶段或创建新项目。暂停、关闭项目功能或关闭其前置开关会阻止项目目标继续被自动选择和调用生活工具；独立于项目的原有目标仍按原规则处理。项目停用不删除记录，不撤销既有主人管理目标/作品的能力。

## 配置与开关

| 配置 | 默认 | 范围 |
| --- | --- | --- |
| `life_projects_enabled` | `false` | 布尔 |
| `project_active_limit` | `2` | 1..4；活动与暂停项目共同计数 |
| `project_max_stages` | `3` | 1..6；创建时冻结，调大不延长既有项目 |
| `project_review_delay_hours` | `24` | 1..168 |

旧配置缺新键仍按默认加载。生效需 `life_enabled`、`workshop_enabled`、`life_decision_enabled` 同时开启。CLI 开启还要求原配置就绪且 `one_shot_verified=true`；不会替主人开启活动总开关、周期调度、公开互动、点赞投币、收藏或自动公开模式。

以下为日后在**隔离测试数据目录**中的操作示例，本轮没有执行真实配置操作：

```powershell
python deploy/bili_activity/ops.py --data-dir <隔离测试数据目录> configure --project-active-limit 1 --project-max-stages 2 --project-review-delay-hours 24
python deploy/bili_activity/ops.py --data-dir <隔离测试数据目录> switch life_projects_enabled on
python deploy/bili_activity/ops.py --data-dir <隔离测试数据目录> switch life_projects_enabled off
```

## 持久化、恢复与回退

`Projects` 构造、状态查看和调度读取不会初始化表。首次创建项目先用 SQLite backup 在数据目录的 `schema_backups/projects-v0-*.sqlite3` 保存迁移前快照，再事务性增加 `project_meta`、`life_projects`、`project_stages`、`project_reviews` 四张表。独立 schema 版本为1；原主库版本与账本保留。发现不完整或未来版本会拒绝操作。

下一阶段使用“预留阶段 → 原 LifeState 创建目标 → 关联目标”的恢复流程，不嵌套原目标事务。预留项冻结问题和稳定来源键；重启后同一阶段找回同一目标，不重复创建。已创建但未关联的目标暂不允许自动执行。原目标名额用满时保留预留项；释放名额后可继续 `advance`。恢复前也可暂停项目。归档仍要求当前阶段有已完成/取消目标，未落实的预留阶段不能直接归档。

每个会话最多保留50个项目（包括已完成/归档），本版没有自动删历史。读取来源时重新核对当前版本和修订状态；来源后来失效会显示 `needs_attention`，不能自动从旧回看继续。已有回看不覆盖、不自动修补已完成作品，需主人核对后按既有目标/作品管理方式处理，或归档后另立项目。

回退优先关闭开关并停止后台，再确认活动已结束；项目表、作品和回看均保留。不要直接恢复迁移前全库快照覆盖之后产生的记录。若换回不认识项目开关的旧程序，应先用原目标工具暂停/取消相关未完成目标，或保持生活活动关闭：旧程序不会识别项目暂停状态。

项目创建、回看、阶段关联和状态改变写入本地 events。项目方法不直接创建 memories 或发送消息；运行结束仍经过原来的 `run_end` 和 LivingMemory 队列策略。开启经历记忆策略时运行自述按该策略处理，关闭该策略时沿用既有活动摘要路径，不额外叠加项目回看写入。

主人日后可在隔离测试会话、低模型额度、公开写入全部关闭的配置下验收：

1. 先完成原单次活动验收，再开启项目功能；确认 `df_project` 已注册，群聊与非主人无法调用。
2. 从一个真实读到资料的有限目标开始，确认它沿用同一个目标和作品版本推进，而不是每轮新建。
3. 完成作品后确认未到回看时间不会启动；到期后观察原调度选择。核对“收获/局限”与实际来源对应，不宣称资料已被事实核实。
4. 回看有后续问题时仅产生一个待做目标；重启后重放 `advance`，确认目标ID不变，后续研究留到下一轮。
5. 两阶段达到预设上限后收尾，空问题提前收尾；暂停、DND和低预算确实阻止下一轮；关闭项目后确认项目目标停止自动推进。
6. 核对QQ联系仍走既有额度与发送链；模型口述分享不算实际送达。核对原LivingMemory行为，不把本地回看保存误报为远端可召回。
